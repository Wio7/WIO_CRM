# Fase F3 - Caja chica mejorada (plan corto)

Spec: `specs/2026-11-09-areas-pendientes-design.md` 3.6 y `specs/2026-11-09-fase-f-apps-y-conexiones-design.md` 2, 4, 6.3.
Rama `aurex/fase-f3-caja`. Sin push, sin SQL contra produccion.

1. **Propuesta automatica** (`src/lib/cash/clasificar.ts`): funcion pura rubro + proyecto desde el texto. Pruebas primero.
2. **Migracion 087** (`087_caja_proyecto_rubro.sql`): `cash_entries.project_id/project_general/rubro`, trigger BEFORE INSERT que toma la clasificacion de un ajuste de sesion (no toca `cash_company_command` ni el historial inmutable), `cash_company_entry` (obligatoria en la app), `cash_classify_entry` (completar luego), `cash_as_user` con proyecto/rubro para WhatsApp, `cash_companies.responsible_user_id`, `cash_form_options`, `cash_management_panel`. Casos en `supabase/tests/087_casos.sql` y prueba PGlite.
3. **API**: `POST /api/caja` usa `cash_company_entry` para gastos nuevos; `GET /api/caja/opciones`, `GET /api/caja/panel`, `POST /api/caja/clasificar`.
4. **WhatsApp** (`asistentes-whatsapp/caja.ts`, `texto.ts`): el borrador lleva proyecto y rubro propuestos o "sin asignar".
5. **UI**: formulario con proyecto y rubro, responsable visible, panel de gerencia (laptop y celular separados), nombre del menu por cuenta.
6. **Verificacion**: suite completa, build, casos SQL en PGlite.
